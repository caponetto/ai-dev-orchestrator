**Diff retrieval strategy (try in order):**

1. Extract `baseRefName` and `headRefName` from the canonical specification's `prMetadata` field. These are the authoritative branch names — do NOT assume `main` or `master`.
2. If the task context provides a repository root, the working tree may already contain the PR code. Check with `git -C <repository_root> log --oneline -1 HEAD` and compare against the expected PR head commit. If HEAD is detached at the PR commit or on the PR branch, the files on disk ARE the code to review — read them directly with `cat` or file-reading tools. Do NOT look for diffs in `.ai/` run directories or prior run artifacts.
3. To obtain the diff, try local git refs. The remote may not be named `origin` — run `git -C <repository_root> remote -v` to discover available remotes, then look for any remote that has the head branch: `git -C <repository_root> branch -r | grep <headRefName>`. Use whatever remote has it (e.g., `git -C <repository_root> diff <remote>/<baseRefName>...<remote>/<headRefName>`). Always pass `-C <repository_root>` so commands target the correct repository.
4. If no remote has the branch refs, use `gh pr diff <PR_NUMBER> --repo <owner>/<repo>` to fetch the diff via the GitHub API.
5. If neither strategy succeeds (no local checkout, `gh` CLI unavailable, API errors), produce a limited-scope review noting which files you could NOT review due to inaccessible diff. Do NOT fabricate or guess at code changes — only review what you can actually read. Cap all findings at `minor` severity and omit the `evidence` field to signal they are unverified.

Once you have the diff, review the actual code changes. When a finding requires understanding code beyond what the diff shows (e.g., tracing a data flow, checking callers, verifying an interface contract), read the full file directly from the working tree (`cat <repository_root>/<path>`) if the working tree is at the PR commit, or use `git -C <repository_root> show <remote>/<headRefName>:<path>`, or fetch via `gh api repos/{owner}/{repo}/contents/{path}?ref=<headRefName>`. Only read the specific files you need — do not read the entire repository.
